1. What is new

  • Screen and 4 buttons on the machine: piece count in big digits, state in colour (green cutting, amber parking/tests, red fault), all settings and tests in menus. The machine no longer needs a PC.
  • Wi-Fi: up to 8 saved networks. At power-on and whenever the Wi-Fi drops, it joins the strongest one in reach. With no saved network in reach it opens its own setup hotspot.
  • One app for phone and PC: same app over USB, over your Wi-Fi, or from anywhere in the world through a free cloud server. Start is a hold button, so a pocket tap cannot start the machine.
  • Safe link: the machine only obeys checked command lines, so the Wi-Fi module's start-up noise can never start it. Cloud commands are signed with the machine password and cannot be replayed.
  • Remote lock on the machine's screen: switch remote control off and phones can only watch (and stop).
  • Also: lifetime piece total, optional buzzer, feed timing adjustable while cutting from the buttons or the app, Wi-Fi module updates over Wi-Fi.

Never have 1+2 and 3+4 ON together: two senders on the machine's receive line.

5. Load the machine sketch (once)

  1. DIP switches: 3 4 ON, the rest OFF. USB cable to the PC.
  2. Arduino IDE: open firmware\FeedCutHMI\FeedCutHMI.ino. Board Arduino Uno, the board's COM port. Upload.
  3. The screen shows STRIP CUTTER v5.0, then READY. All settings start at the defaults (70 mm, 1000 mm/s, 6000 mm/s², timing 20 ms, correction 1.1494 / −5.86).
  4. If the picture has wrong colours, a coloured edge or is shifted: Machine → Screen type (try 0, 1, 2). Upside down: Machine → Flip screen.

6. Load the Wi-Fi sketch (once)

  1. Arduino IDE → File → Preferences → Additional boards manager URLs: http://arduino.esp8266.com/stable/package_esp8266com_index.json. Then Tools → Board → Boards Manager → install esp8266 (3.1.x).
  2. Sketch → Include Library → Manage Libraries: install WebSockets by Markus Sattler and PubSubClient by Nick O'Leary.
  3. DIP switches: 5 6 7 ON, the rest OFF.
  4. Open firmware\StripCutterWiFi\StripCutterWiFi.ino. Tools: Board Generic ESP8266 Module, Flash Size 4MB (FS:none OTA:~1019KB), CPU Frequency 160 MHz, Upload Speed 115200, the same COM port. Upload. If it does not start, press the board's reset button and upload again.
  5. DIP switches back to 1 2 ON, the rest OFF. Unplug and replug the power.

Later updates of this sketch can go over Wi-Fi: Tools → Port → the network port stripcutter, password = machine password. The module accepts them only while the machine is idle.

The upload log shows Detected flash size. If it says 1MB, choose Flash Size 1MB (FS:none) instead; everything works except updates over Wi-Fi.

7. First Wi-Fi setup (from your phone)

  1. Power on. With no saved network, the machine opens the hotspot StripCutter-Setup (password stripcutter). The screen's Wi-Fi & remote page shows setup hotspot, 192.168.4.1.
  2. Join it with the phone. The control page opens by itself (or open http://192.168.4.1). Machine password: stripcutter.
  3. Wi-Fi tab → Find networks → tap your network → its password → Save network. Add every network the machine may meet (home, workshop, phone hotspot): up to 8.
  4. The machine joins the strongest one; the screen shows the network and its address. The hotspot closes 3 minutes later. Put the phone back on your normal Wi-Fi and open http://stripcutter.local (or the address from the screen).
  5. Wi-Fi tab → Machine password: change it from stripcutter to your own (8 or more characters). The Wi-Fi module restarts (the machine keeps running) and from then on it is also the hotspot and update password.
At a new place with none of the saved networks, the hotspot opens by itself after 30 s. You can also open it from the machine: Wi-Fi & remote → Setup hotspot (10 minutes). Forgot the password? Wi-Fi & remote → Forget Wi-Fi clears the networks and sets the password back to stripcutter.

The ESP8266 uses 2.4 GHz Wi-Fi with a normal password (WPA2). Hidden networks and hotel-style sign-in pages are not supported.

Wi-Fi details on the machine's screen

Wi-Fi & remote → Wi-Fi details (needs machine sketch 5.1 and Wi-Fi sketch 1.1) shows what the Wi-Fi module knows. UP / DOWN turn the page, OK tries the saved networks again at once (and scans again), STOP goes back.

9. Using the app

  • Same Wi-Fi: open http://stripcutter.local or the address from the screen. On the phone, use "Add to Home screen" for an app icon. (Android phones that do not find .local names: use the address.)
  • USB on the PC: DIP 3+4 ON, double-click Start Strip Cutter.bat → Connect over USB. The board restarts when the port opens; the app holds its auto start.
  • Run tab: count, hold-to-start, Stop and Stop now, feed timing − / + while cutting, timing bar (blue feed inside the green open window), set or reset the count.
  • Settings tab: changed boxes turn amber; Send stores them in the machine. Start stays locked while a change is not sent. The length correction can be worked out from measured pieces.
  • Tests tab: feed one / many / until stopped, roller one turn, jog, one cut, park, switch test.
  • Wi-Fi tab: status, saved networks, scan and add, cloud settings, name, password, hotspot, restart.
  • Esc on the PC = stop now. The red STOP in the top bar = stop now, on every tab.

10. From anywhere (cloud)

The machine keeps one connection open to a cloud message server; the app connects to the same server. Nothing on your router needs changing.

a. Free cloud server (once, 5 minutes)

  1. Sign up at console.hivemq.cloud, create a Serverless (free) cluster.
  2. In the cluster: Access Management → add credentials (user name + password), permission Publish and Subscribe.
  3. Note the cluster URL, e.g. abc123.s1.eu.hivemq.cloud.

b. Tell the machine (from the app on the same Wi-Fi)

  1. Wi-Fi tab → Cloud: tick Connect the machine to the cloud, enter the cluster URL, user name and password, Save cloud settings.
  2. Status shows Cloud: online after a few seconds, and so does the machine's screen. The phone you did this on is now set up for the cloud too.

c. The app online

Away from the machine the phone needs the app from somewhere on the internet. It is published with GitHub Pages from the project repository github.com/sri-automation/strip-cutter:

https://sri-automation.github.io/strip-cutter/

The repository's index.html is the same file as app\StripCutter.html. After changing the app, run python tools/make_app_gz.py (it updates index.html and the Wi-Fi module's app_gz.h), commit, and load the Wi-Fi sketch again.

The page holds no passwords; each phone keeps its own. On another phone: open that address → From anywhere → cloud address wss://abc123.s1.eu.hivemq.cloud:8884/mqtt, user, password, machine ID (shown on the Wi-Fi tab, e.g. stripcutter-a1b2c3) → connect → machine password. Or use Copy setup link on the Wi-Fi tab to fill all but the passwords.

The online copy reaches the machine only through the cloud (browsers do not let an https page talk to the machine directly). At the machine, use http://stripcutter.local.

11. Safety

Fit a real emergency-stop switch (mushroom head, latching) in the wiper motor's 12 V supply. The STOP button and the app's stop are software; an E-stop cuts the power whatever the electronics do.
  • Someone working at the machine: set Wi-Fi & remote → Remote control to OFF. Phones can then watch and stop, but not start or change anything.
  • Start from the app needs a 1-second hold. Remote starts happen out of sight: make sure nobody is at the knife.
  • Auto start is off by default. Turn it on only where a machine starting by itself after a power cut is safe.
  • Wi-Fi drop while cutting: the machine keeps cutting (it does not need Wi-Fi). Stop it with the button, or from the app once it reconnects.

The real machine sketch ran in a simulator with motor, switch and screen; the real Wi-Fi core ran on a PC; the app was driven in a browser over Wi-Fi, cloud (a local test server) and USB, including wrong passwords, a jam, stop-now, the remote lock and the stop count.
